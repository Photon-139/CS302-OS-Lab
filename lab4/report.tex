\section{Setup and Assumptions}

\subsection{Simulated system}
The simulator models a 32-bit virtual address space with 4\,KB pages, so an address splits into a 20-bit virtual page number (VPN) and a 12-bit offset, giving $2^{20}$ virtual pages. Only the lower 32 bits of each trace address are used (the traces contain addresses wider than 32 bits). The TLB has 128 entries, is fully associative with LRU replacement, and is empty at the start of every run. Instruction/data and read/write flags in the traces are not used.

\subsection{Cost model}
Every trace line is one memory access of the benchmark. Let $w$ be the number of memory accesses needed to walk the page table ($w=1$ for the single-level table, $w=2$ for the two-level table). The cycles charged per access are:
\begin{center}
\begin{tabular}{lc}
\toprule
Case & Cycles \\
\midrule
No TLB & $200\,w + 200$ \\
TLB hit & $1 + 200$ \\
TLB miss & $1 + 200\,w + 200$ \\
Page replacement (extra, Part IV only) & $+20{,}000{,}000$ \\
\bottomrule
\end{tabular}
\end{center}
The final 200 cycles is the access to the data itself. A page fault into a free frame costs the same as any page-table walk and no disk time, since the first pages come for free; disk time is charged only when a resident page has to be replaced. We do not model where the page table itself is stored in physical memory: page-table pages do not occupy frames, and only the cost of walking them is charged.

\subsection{Frame management scheme}
\begin{itemize}
\item \textbf{Parts I--III} (more frames than pages): frames are handed out sequentially, $0,1,2,\dots$, in the order pages are first touched, and are never freed. The number of frames used is therefore the number of distinct pages touched.
\item \textbf{Part IV} (limited frames): frames are initially handed out the same way. Once all frames are in use, a page fault evicts the least recently used page. Recency is kept in a doubly linked list over the frames; every access (TLB hit or not) moves the accessed page's frame to the most-recently-used end, and the victim is the frame at the least-recently-used end. On eviction the simulator removes the victim from the page table, invalidates its TLB entry (so the TLB can never return a translation to a frame that has been reused), charges the disk cost, and gives the freed frame to the faulting page.
\end{itemize}

\subsection{Page tables}
The \emph{single-level} table is an array of $2^{20}$ entries indexed by the VPN. The \emph{two-level} table splits the VPN into a 10-bit directory index and a 10-bit second-level index. Second-level tables (1024 entries each) are allocated only when the first page they cover is mapped, and are freed when their last valid entry is removed. Each second-level table therefore covers 1024 pages (a 4\,MB region of the address space).

\subsection{Statistics}
\begin{description}
\item[A. Frames used] the peak number of frames in use.
\item[B. Hot pages] the number of accesses to every virtual page, from which the cumulative access share of the hottest pages is computed.
\item[C. Cycles] total cycles over the trace, using the cost model above.
\item[D. Page table utilization] number of distinct pages accessed divided by the number of page table entries allocated. For the single-level table the denominator is $2^{20}$. For the two-level table it is $1024 \times$ (number of live second-level tables); the fixed 1024-entry top-level directory is \emph{not} counted.
\item[E. Hash] $H \leftarrow (H \oplus \mathit{frame}) \times 1099511628211 \pmod{2^{64}}$, applied once per access with $H=0$ initially.
\end{description}

\subsection{Environment}
All numbers come from one run of each program on an Intel Core Ultra 7 258V (8 logical CPUs, 30\,GB RAM), compiled with g++ 13.3.0 using \texttt{-std=c++17 -O2}. The ten benchmark traces contain between 11.5 and 12.9 million accesses each. Traces are streamed from disk in 1\,MB chunks and parsed by hand.

\section{Part IV: Limited Physical Memory}

\section{Notes and Limitations}
\begin{itemize}
\item Page table utilization for the two-level table excludes the fixed 1024-entry directory. It is only reported for Parts I--III; in Part IV second-level tables can be freed by evictions, so the value at the end of a run is not comparable.
\item ``Page fault rate'' in Part IV is faults per access including compulsory first-touch faults. The eviction rate (replacements per access) is also in \texttt{results/part\_iv.csv}.
\item Page-table storage is not modelled as using physical frames, so it does not compete with the benchmark's pages for memory in Part IV.
\item Timing figures come from a single run on one machine.
\end{itemize}
